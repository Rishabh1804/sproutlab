Self-review is blind to its own coverage gaps

The reviewer's value is re-deriving the list — not re-reading it.
Date  2026-06-10 Operator  Lyra (The Weaver) Arc  Ceres seating · PR #245 Status  candidate Codex canon

Seating Ceres meant propagating one fact — the Care Region splits into Care (Maren) and Nutrition (Ceres) — through ~21 surfaces. The author reviewed her own propagation and called it complete: "no half-updated surface." The independent pass found four she had missed — for the same structural reason she missed them while propagating.

The pattern

You cannot audit a checklist for what it doesn't contain by re-reading it

The author builds a working set of "surfaces that assert this fact," propagates against it, then reviews against the same set. The surfaces missed in propagation are missed in review for the identical reason — they were never on the list being carried. Self-review reproduces the author's blind spots by construction.

All real, all mechanical, none caught by the author. The LOC case is the sharpest: changing some rows is exactly what hid the un-changed ones — the diff reads as "I updated the LOC," so the eye marks it done.

The doctrine

  1. An independent reviewer is a fresh derivation of the list, not a second read of it. Cipher didn't re-read the self-review; it asked "where must this fact be true?" from scratch and reached surfaces the author's working set never held. That re-derivation is the whole value — a reviewer who trusts the author's coverage map inherits the author's blind spots.
  2. This is why the Cipher Edict-V pass is load-bearing even when the Governor audit is waived. A docs/tooling-only change waives the code audit (no Capital code moved) — but cross-cutting consistency is exactly where self-review fails. Broad mechanical propagation is the canonical generator of "half-updated surface" bugs, and the author is its worst auditor. Docs-only changes are more propagation-shaped, not less.
  3. Generated artifacts amplify it. The same session's silent render bug — the Nutrition province dropped from the Province-Map cardOrder — is the same failure in another register: the generator ran cleanly and produced a complete-looking artifact one province short. A clean exit code is not coverage.

How to apply

  1. On any one-fact-many-surfaces change, the final-pass reviewer re-derives the surface set independently. Brief it as a question ("where must X be true?"), never a checklist ("confirm X in these files").
  2. Never waive the cross-cutting final-pass on a docs-only / governance change. Waive the Governor code audit if no Capital code moved; keep Cipher.
  3. For generated artifacts, verify the rendered output — grep the artifact for what should now be present — not just the build exit.

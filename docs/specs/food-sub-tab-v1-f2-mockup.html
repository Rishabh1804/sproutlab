F-2 — FOB Feed sheet redesign (revised)

Mockup v2 — after Architect ratification of six scoping questions. Target surface: FOB → FEED Log Feed sheet (the canonical meal-entry surface today). The diet Log sub-tab scaffold from PR #165 stays as-is; F-3 fills it as the richer review surface. Four scenarios: 3-tap repeat · 4-tap combo template · 6-tap novel · per-food quantity stepper.

spec: docs/specs/food-sub-tab-v1.md data: 79 days of ziva_feeding analyzed tap budget: 3 (repeat) / 6 (novel) — HARD F-1: PR #165 F-5 normalizer: after F-2

Six ratifications carried into this revision

  • 1. Alternative path — F-2 = FOB Log Feed sheet only. Diet Log sub-tab scaffold (PR #165) untouched; F-3 fills it as the richer review surface.
  • 2. Dynamic combos — rolling 14d top-N per meal-slot. Intelligence layer reserves a slot for curated combo fallback (covers cold-start).
  • 3. Per-meal intake kept — Few bites / Half / Most / All as secondary field; defaults to "Most" (0.75). Honest baseline: parents tap UP to "All" when Ziva finishes everything, or DOWN to Half/Few when she doesn't. "All" as default would bias the data upward (busy parents won't step-down on a normal day).
  • 4. Quantity defaults in NUTRITION — extend rows with defaultQty + defaultUnit (data.js, Kael's region; single source of truth; audit-gate-friendly).
  • 5. Hard tap-budget limits — 3-tap repeat / 6-tap novel enforced as build-time regression guards. Tighten/loosen after live use.
  • 6. "Same as lunch (today)" for dinner — green light. Data shows 46% of days have identical lunch + dinner — biggest single-tap win available.

DETAIL

Per-food quantity stepper · NUTRITION defaults

Each item row carries [− qty unit +] inline. Defaults come from the food's NUTRITION row (defaultQty + defaultUnit per ratification #4). Single tap steps ± by the food's natural increment (Ghee = ±½ tsp; Walnut = ±1 pc; Avocado = ±¼ pc). Long-press the qty value opens a numeric keypad for exact entry. Adjusting qty does not count toward the tap budget — it's editing, not entry. The default values mean the common case requires zero qty taps.

Why per-food + per-meal both kept: per-food qty answers "how much of each thing"; per-meal overallIntake answers "did Ziva finish what was offered". The second covers "had 2 bites and pushed away" (intake = Few bites) even when all items are listed — a distinct semantic. Default = "Most" (0.75) for honest baseline: parents tap UP to "All" when Ziva finishes everything, or DOWN to Half / Few on harder days. "All" as a default would silently bias the data upward — busy parents wouldn't step-down on a normal day. "Most" reflects the realistic typical meal where Ziva eats most-but-not-all.

What gets written to disk

F-2 emits the structured shape declared in PR #165 (data.js — _FEEDING_V1_SCHEMA_VERSION = 1). Per-food qty + unit live on each item; per-meal overallIntake sits alongside. Legacy text + {meal}_intake + {meal}_time compat fields generated so existing readers (home tab "Today's Meals" summary, diet stats, combo intelligence) keep working until F-5 normalizes everything.

Migration policy unchanged from spec §3: lazy. No rewrite of existing 79 days of legacy string records. New writes emit structured; old reads come through parseFeeding (F-5) which tolerates both shapes. sourceFlow field new in v2 mockup — lets us measure which entry path parents actually use (telemetry for "is the 3-tap path actually getting used 70% of the time, like the data suggests it could?").

Autofill intelligence — four layers

L1
Repeat — "Same as yesterday's B" / "Same as lunch (today)" One-tap full-meal apply. Surfaces the most recent same-slot meal (or, for dinner, today's lunch — per ratification #6, the 46% match rate makes this the single biggest UX win). Source: ziva_feeding · last 1-7 days · per meal slot
L2
Combo template — "Your usual breakfast" Rolling 14d top-N combos per meal slot. Currently the data has two co-tied top combos (7×) for breakfast — both surfaced. Confidence % shown. Source: dynamic 14d rolling window · cold-start fallback to CURATED_COMBOS intelligence-layer registry (covers first 14 days of use; ratification #2 reserves this slot)
L3
Next-item prediction ribbon After each item added, ranked "+ X" chips by co-occurrence with current item set. Refreshes on each add (e.g., Avocado→Blueberry@94%; Avocado+Blueberry→Mango@42%). Confidence % shown — Honesty axis honored. Source: dynamic 14d pair-count map · keyed on items already in current meal
L4
Typeahead As-you-type match against NUTRITION + parent's introduced foods (ziva_foods list). Existing typeahead pattern extended to surface the food's default qty inline in the dropdown row. Source: NUTRITION (live) · ziva_foods (47 introduced foods)

Open issues — confirm before I open IMPL commits

  1. Meal-slot inference — Scenario 1 assumes "morning → B, midday → L, evening → D". Need bands. Proposed: 5-11a → B, 11a-3p → L, 5-9p → D, anywhere else → S (default selected). Parent can override with 1 tap. Confirm bands?
  2. 2-second auto-save window — Scenario 1's "tap chip → 2s countdown → save" is novel. Alternative: explicit Save button always required (=4 taps for repeat path, but no surprise saves). I lean auto-save because the "Logged · undo" banner gives 8s safety net. Confirm?
  3. Quantity step semantics — fractional steps for things like Avocado (¼ pc step) require a UI for ¼ / ½ / ¾ display. Proposed: store as floats; render as unicode vulgar fractions (¼ ½ ¾) or "0.25" if outside the common set. Long-press qty value opens numeric keypad for exact entry. OK?
  4. Curated combo registry shape — for L2 cold-start fallback (ratification #2). Proposed shape: { slot: 'breakfast', items: ['Ragi porridge', 'Ghee', 'Banana mash'], rationale: 'pediatrician-suggested', minAgeMonths: 6 } in data.js. Could seed with 4-6 entries (breakfast/lunch/dinner/snack standards) until rolling-14d has signal. Confirm rough shape?
  5. Diet Log sub-tab — F-3 surface — by ratification #1, F-2 only touches FOB. The F-1 scaffold's diet Log sub-tab stays as a placeholder with "Tap to open FOB Log Feed" CTA? Or empty? Or shows today's logged meals as read-only review? I lean read-only review (zero new IMPL surface, but the sub-tab earns its existence).
  6. What does the "Skip remaining" link do in the home tab Today's Meals card (screenshot 2)? If a parent taps "skip remaining" — does it mark lunch + dinner as intentionally-skipped vs missing-data? F-2 might want to write { skipped: true } on those slots for honesty in nutrition snapshot computation.
  7. Tap-budget regression-test fixture — to make ratification #5 enforceable. Proposed: tests/e2e/food-fob-tap-budget.spec.ts with two fixtures: (a) yesterday's-breakfast-present → 3 taps from FOB to Logged; (b) novel "av-bl-ma" meal → 6 taps from FOB to Logged. Fails the build if either exceeds. Acceptable as a guard?

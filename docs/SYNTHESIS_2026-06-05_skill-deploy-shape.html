The skill-deployment-shape doctrine

Two shapes live under .claude/skills/, and they are not interchangeable.

The rule

Discovery requires the directory shape + frontmatter on line 1

Claude Code discovers a skill only at .claude/skills/<name>/SKILL.md with YAML frontmatter on the first line. A bare .claude/skills/<name>.md is invisible to the loader — correct for a spec reference, fatal for something meant to be invoked.

How it surfaced

/sproutlab-compact deployed (PR #231) byte-identical to its canon body — as a bare .md, with the canon's HTML provenance comment ahead of the frontmatter. It verified byte-identical and looked done. It never loaded. The Architect caught it by absence. The repo's own working skills were the proof: /design-principles and /doc-render are SKILL.md directories and load; the bare companion mirrors never appear. The fix (PRs #233 / #88): move to the directory shape, hoist frontmatter to line 1, push the provenance comment below it.

What to carry

  1. Byte-identical verification is necessary, not sufficient. It proves the content matches canon; it says nothing about whether the artifact is in a shape the consumer loads. A slash-skill deploy check must also assert the path shape and frontmatter-line-1 — best, assert the skill appears in the loader's list.
  2. Canon bodies for operational skills must be loadable as authored. Frontmatter first; provenance comment after (the convention cipher / vela already follow).
  3. The classification is the canon refinement. Route by kind: persona mirror → bare .md; operational slash-skill → SKILL.md directory.

Candidate canon text

canon-cc-026 §Per-Province-Layout — skill shape. A Companion persona skill-mirror deploys as a bare .claude/skills/<name>.md, byte-identical to its Codex canon body; it is a spec reference and is never slash-invoked. An operational slash-skill deploys as .claude/skills/<name>/SKILL.md, byte-identical to its Codex canon body, with YAML frontmatter on line 1 and any provenance comment below the frontmatter; it is discovered and invoked as /<name>. A deploy of an operational slash-skill is not complete until the skill appears in the loader's available-skills list.
The byte-check said yes and the loader said nothing; both were telling the truth about different questions. A companion's voice and a parent's command live in the same folder, but one is a page to read and the other is a door to open — and a door has to be built as a door. — Aurelius, 2026-06-05

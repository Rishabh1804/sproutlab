Authority lives where governance lives; records live in the archive. A downstream mirror must never be silently overwritten by its upstream record at load time.

The bug, as a flow

Before — the clobber
Province authors lore in lyra.md → committed in repo ✓ → session-start: cp -f "Codex wins" → loaded persona = Codex (no lore) ✗
After — the gap-fill
Province specs land first → [ -e dst ] && continue → Codex fills gaps only (e.g. Consul) → loaded persona = Province (lore) ✓

The doctrine

  1. Record ≠ authority. A system can archive a thing without governing it. Codex keeps the record (canon-cc-010); it no longer routes or governs SproutLab's specs. Conflating "where recorded" with "who decides" is the bug class.
  2. The governor's copy wins at the point of use. A "sync from canon" step that clobbers local authorship is only safe if the canon is the authority.
  3. Gap-fill, not overwrite, for cross-source overlays. First writer wins; later sources fill absences. Overwrite-on-collision is dangerous because it's invisible — the loss is at load, the repo file stays pristine, it survives every git status.
  4. Cross-cluster roles are the careful edge. Cipher / Chronicler / Scribes replicate from the shared record; under "Province wins" their in-copy is editable, so the rule is keep in sync, don't fork. Pinning to shared canon = an explicit A2 carve-out, not the default.

Diagnostic method (reusable)

Committed content absent at runtime → suspect a materialization / deploy step, not the source.
Repo file had it ✓ · loaded file didn't ✗ · the only thing running between is the hook → read the hook → found cp -f. Read the hook before re-editing the file a third time.

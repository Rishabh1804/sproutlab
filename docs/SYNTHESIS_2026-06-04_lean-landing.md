# Synthesis — 2026-06-04 — The Lean Landing arc

**Companion:** Lyra (The Weaver)
**Arc:** Building SproutLab's calm front door (PR #219) and refining it (PR #226).

---

## The shape of the work

The app used to open onto a 16-section data cockpit — the wrong front door for a parent holding a baby at 2 AM. This arc replaced it with a **calm landing**: a warm-wave hero, one honest "today" line, three soft doors (Log / Today / Ask), and a footer. The dense cockpit didn't go away — it became "Today," one tap behind. The organizing principle: **calm by default, but Care pre-empts the calm.** A fever, an overdue vaccine, a due Vit D3 dose steps forward on its own, loud-rose, and routes the parent to the fix.

Three durable patterns surfaced — each a candidate for Codex canon.

---

## Pattern 1 — Deep-link to the fix, not the inventory

**Surfaced by:** the Vit D3 bug (#226). The "Vitamin D3 due today" pre-empt deep-linked to `medMedsCard` — the Meds *inventory* card (add / stop / delete a medication). The parent arrived and found **no way to record the dose**. The signal was correct; the destination was a dead end.

**The pattern:** an alert or pre-empt that asks the user to *act* must land them on the surface where the action lives — the logging affordance, the resolve button — **never** a read-only summary or management card that merely *describes* the thing. The fix routed the med pre-empts to the Home "Today" reminder cards (`supp-alert-${idx}` → Done now / Done at… / Skip; `missed-${name}-${ds}` → Was given / Not given) — where dosing actually happens.

**The subtle part — id-contract alignment across functions.** The deep-link target `supp-alert-${idx}` is generated by one function (`renderRemindersAndAlerts`) and *referenced* by another (`getActiveCareSignals`). They align only because both derive `idx` from the byte-identical `meds.filter(m => m.active)` in the same order. When a deep-link target is an id minted elsewhere, the contract is "same derivation, same order" — and that invariant deserves a comment at both ends (it now has one). Maren and Cipher both verified the seam holds; a divergence would have silently timed out the scroll-poll.

## Pattern 2 — Crowd-fit the hero

**Surfaced by:** the Architect's observation that when Care pre-empts stack at the top, the Emergency card falls below the fold.

**The pattern:** a hero that **yields vertical space** when higher-priority content crowds the viewport. `_ldFitHero` measures the Emergency card's bottom against `window.innerHeight`; if it's below the fold, the warm-wave hero collapses to a compact "Today so far · Start with [picker]" row — keeping the safety-critical Emergency reachable without a scroll. It **re-measures from the full state** on resize/rotate, so it relaxes back when the viewport has room (no sticky-crowded state, no oscillation — compacting only ever shrinks).

**Why measure, not count.** The trigger is the *actual* layout overflow, not a heuristic count of Care cards — faithful to the real constraint ("does Emergency fit?") across devices, zoom tiers, and variable card heights. Measured in a `requestAnimationFrame` after `innerHTML` (layout + fonts settled), before the fade-in animation runs (so the transform doesn't skew the read).

## Pattern 3 — Relabel, don't rename (the string-contract preserve)

**Exercised at scale by:** the default-flip (#219). The id `home` was threaded through `TAB_ORDER`, header toggles, FAB actions, sync, and a dozen `curTab === 'home'` re-render guards. Renaming it to make the new lean screen the default would have rippled through every reference.

**The pattern:** introduce the new id (`landing`) as the default; **keep** the old id (`home`) bound to its surface and change only the *label* ("Today"). Preserve the string contract with a **derived id-set** — `PANEL_IDS = [...new Set([...TAB_ORDER, 'home'])]` — so every active-panel resolver still recognizes `home` even though it left the nav rail (`TAB_ORDER`). Kael's K-1 caught the one resolver that still read `TAB_ORDER` instead of `PANEL_IDS`; the lesson is that a derived set only works if *every* consumer is migrated to it.

## Meta-pattern — the cross-cutting seam Edict V exists to catch

Cipher's #219 final-pass found `handleSafeExit` still treating `home` as the exit "home base" after the front door became `landing` — so an exit gesture from the landing would pull the parent *into* the cockpit. **No single Governor owned it**: it wasn't Care data (Maren), wasn't the render (Vela), and Kael's pass named the migration/dispatch/sync resolvers but not the exit gesture. It lived in the seam between "the new default screen" and "the exit gesture's relationship to it." That is precisely the class of bug the cross-jurisdiction final-pass exists to catch — the integration seam that falls between the per-jurisdiction audits. The canon-cc-008 chain earned its last link this arc.

## What to carry to Codex

1. **"Deep-link to the fix, not the inventory"** — an actionable alert routes to the action surface, never a read-only card. (Candidate canon.)
2. **"Crowd-fit the hero"** — measure the safety-critical element against the viewport; yield hero space when it's crowded; relax back. (Candidate canon.)
3. **"Relabel, don't rename"** — preserve a threaded string-contract via a derived id-set; migrate *every* consumer. (Candidate canon.)
4. **Edict V finds seams, not violations** — the cross-cutting pass's value is the bug no jurisdiction owns. (Reinforces existing doctrine.)

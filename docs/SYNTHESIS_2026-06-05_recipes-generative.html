The app could track a baby's food but never help a parent make a meal. This arc gave it a Recipes tab — first the plumbing (a cited corpus, a meal-slot catalog, a "Can I give this?" that stops handing a parent an empty recipe for honey), then the full generative food system: a colour fingerprint weighted by what's in the bowl, a voice composed from the ingredients, a warm-wave sheen in time with the app's front door.

Four durable patterns

Pattern 1 · safety

Trace-for-cosmetics ≠ trace-for-safety

The fingerprint excludes "trace" ingredients so colours don't mud. The tagline composer reused that exclusion — and honey, filtered as trace, never reached the composer, so the rose "honey — only from age 1" strict lead was dead code. A warm honey-recipe voice would have shipped with the caution silently gone.

Maren and Kael caught it independently. The §9 sibling of M-γ-1: a consolidation for presentation must never drop a safety obligation.

Pattern 2 · process

Render-first tier-discussion

When an upgrade exceeds a locked design, present a small ladder of options — each tied to a real artifact (a record, a canon section, a live surface). The Architect picks the altitude; then build render-first, preview as sign-off, before the gate. Tier A / B / C → C chosen.

Pattern 3 · craft

Live-pattern reuse over parallel invention

The Tier C hero reused the lean-landing's shipped @keyframes ld-wave rather than authoring a new sheen. Three warm-wave surfaces now beat in unison at 4.4s, share one reduced-motion contract, and inherit the prior Governor sign-off — one CSS line, not a new motion system.

Pattern 4 · architecture

One resolver, two surfaces

"Can I give this?" runs through one shared _resolveRecipeAnswer on both the Patterns bar and Home Q&A — no two-path divergence (the fish/milk defect class). Kael proved the gates algebraically equal; the refactor to shared (not merely equal) is a pinned carry-forward.
